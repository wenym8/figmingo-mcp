figmingo-mcp 安装与使用指南

本指南面向新用户，覆盖从安装、配置、插件导入到第一次调用工具的完整路径。 看完这页，你应该能在任意支持 MCP 的 AI 客户端里读取 Figma 文件，并把 HTML 1:1 复刻进 Figma 画布。

一、快速开始（推荐）

需要 Node.js ≥ 18。没装请先去 nodejs.org 安装 LTS 版。

macOS / Linux · 一键安装

curl -fsSL https://raw.githubusercontent.com/wenym8/figmingo-mcp/main/scripts/install.sh | bash

安装器会：检测 Node、全局安装 figmingo-mcp、下载 Playwright Chromium（约 170MB，一次性）、给常见 AI 客户端写入 MCP 配置、把伴侣插件复制到 ~/.figmingo/plugin，并在桌面创建 figmingo-plugin 快捷方式。

Windows · 一键安装

iwr -useb https://raw.githubusercontent.com/wenym8/figmingo-mcp/main/scripts/install.ps1 | iex
安装器是幂等的：重复运行不会覆盖已有的 Figma Token，也不会删除已有配置。

二、获取 Figma Personal Access Token

  1. 打开 Figma 并登录。
  2. 点击头像 → Settings → Security → Personal access tokens。
  3. 点击 Generate new token，给一个名字（例如 figmingo-mcp）。
  4. 勾选 File content 与 File metadata 读权限（Dev resources 可选）。
  5. 复制生成的 figd_... 字符串。
这条 Token 只保存在你本地配置里，不会上传到任何中转服务器。

三、客户端配置

安装器已自动写好配置。如果跳过了，或想手动添加，参考下面：

通用 JSON 配置（Cursor / VS Code / Claude Code / Kimi CLI） 
{
  "mcpServers": {
    "figmingo": {
      "command": "npx",
      "args": ["-y", "figmingo-mcp"],
      "env": { "FIGMA_API_KEY": "figd_你的Token" }
    }
  }
}

把这个 JSON 合并进对应文件：

  • Cursor：~/.cursor/mcp.json
  • Claude Code：~/.claude.json
  • Claude Desktop：macOS ~/Library/Application Support/Claude/claude_desktop_config.json；Linux ~/.config/Claude/claude_desktop_config.json；Windows %APPDATA%\Claude\claude_desktop_config.json
  • VS Code：macOS ~/Library/Application Support/Code/User/mcp.json；Linux ~/.config/Code/User/mcp.json；Windows %APPDATA%\Code\User\mcp.json
  • Kimi CLI：~/.kimi-code/mcp.json（旧版也读 ~/.kimi/mcp.json）
Codex CLI · TOML 配置 
[mcp_servers.figmingo]
command = "npx"
args = ["-y", "figmingo-mcp"]

[mcp_servers.figmingo.env]
FIGMA_API_KEY = "figd_你的Token"

写入 ~/.codex/config.toml。安装器首次修改时会自动备份原文件到 config.toml.figmingo-bak。

如果你用 fnm / nvm / Homebrew 装的 Node，安装器会自动把配置写成“绝对 node 路径 + 脚本路径”的形式，避免 GUI 客户端因为 PATH 太干净而找不到 node。

四、安装 Figma 伴侣插件（写回画布必须）

读取工具直接走 REST API，但写入画布需要伴侣插件做本地桥接。

1

打开 Figma 桌面端（桌面版才能跑开发插件，浏览器版不支持）。

2

点击菜单 Plugins → Development → Import plugin from manifest…。

3

在文件选择器里选中桌面上的 figmingo-plugin 文件夹，再选里面的 manifest.json。

如果没看到桌面快捷方式，也可以按 ⌘+Shift+G 直接粘贴路径：

~/.figmingo/plugin/manifest.json
4

导入一次后，每次需要写画布时，从 Plugins → Development → figmingo 启动插件。

插件 UI 会显示一个状态面板：● 已连接 / ○ 连接中 / ✕ 失败原因。保持插件窗口运行即可。

插件文件位置

  • 本体：~/.figmingo/plugin/manifest.json
  • 桌面快捷方式：~/Desktop/figmingo-plugin（Windows 为 %USERPROFILE%\Desktop\figmingo-plugin）

五、启动与环境自检

AI 客户端一般通过 stdio 自动拉起 MCP 服务器；你通常不需要手动启动它。但如果想验证安装是否完整，运行：

figmingo-mcp doctor

它会逐项检查 Node、Token 有效性、Chromium、插件文件版本、客户端配置、桥端口，全部通过时退出码为 0。

想手动启动服务器（例如测 HTTP 模式）：

# stdio 模式（AI 客户端默认）
figmingo-mcp

# Streamable HTTP 模式
figmingo-mcp --http --port 3845

# 其他常用命令
figmingo-mcp cache-clear
figmingo-mcp --help

常用启动参数：

参数说明
--token <pat>临时指定 Figma Token
--http启用 Streamable HTTP
--port <n>HTTP 端口（默认随机）
--bridge-port <n>插件桥端口（默认 39220）
--no-bridge禁用写桥
--cache-ttl <min>缓存时间（分钟）
--no-cache禁用磁盘缓存

六、基础使用示例

配置完成后，重启你的 AI 客户端，然后在对话里直接要求调用工具。下面是常用工具的示例：

whoami read

验证 Token 是否有效，查看限流余量和缓存状态。

请调用 whoami 检查 figmingo-mcp 是否连上。

get_design_context read

获取简化版节点树：绝对坐标、auto-layout、填充/描边/效果、文字样式。

读取 Figma 文件 https://www.figma.com/file/XXXX/YYY?node-id=1%3A2 的设计上下文。

get_screenshot read

把某个 Figma 节点导出为 PNG/JPG/SVG/PDF。

导出 https://www.figma.com/file/XXXX/YYY?node-id=1%3A2 为 PNG，scale 用 2。

download_assets read

批量导出节点 + 原始图片填充，生成资产清单。

下载这个 Figma 文件里的所有图标和图片到 ./assets。

get_html_replica_spec replica

为 HTML 复刻生成一份优化过的 spec：绝对矩形、计算排版、颜色、渐变、资产清单。

从这个 Figma 节点生成复刻 spec，保存到 ./spec.json。

import_html_replica write

把 HTML 文件或 URL 一键导入 Figma 画布（需要伴侣插件已连接）。

把 ./cart-final.html 一比一复刻进当前 Figma 文件。

七、HTML 1:1 复刻标准流程

figmingo-mcp 的核心闭环：从 Figma（或任意参考图）拿到 spec → 生成 HTML/CSS → 验收 → 导入 Figma。

  1. 提取设计 spec：用 get_html_replica_spec 拿到绝对坐标、字体、颜色、资产清单。
  2. 写 HTML/CSS：按 spec 还原页面。复刻经验详见 docs/REPLICA-PLAYBOOK.md。
  3. 渲染截图：用 render_html_screenshot 在 Chromium 里截图。
  4. 验收：用 verify_html_parity 或 compare_html_to_image 跑三关验收（内容、结构 ±4px、视觉像素 diff ≤ 1%）。
  5. 导入 Figma：用 import_html_replica 把 HTML 写回画布。
  6. 微调：如未通过，看 diff 图的 band 定位，改 HTML 后再跑。
复刻时先把字体锁定。Figma 没有某些商业字体（如 Roobert）时，会降级为 Inter，字形宽度差异会拉高像素 diff。

八、常见问题与排错

AI 客户端里没有出现 figmingo 工具
  • 确认客户端配置文件中 mcpServers.figmingo 已写入。
  • 重启 AI 客户端。
  • 查看客户端日志，确认 npx -y figmingo-mcp 能被正常拉起。
插件一直显示“connecting…”
  • 确认 MCP 服务器已启动（AI 客户端会自己拉）。
  • 确认 Figma 是桌面端，不是浏览器版。
  • 检查 39220 端口是否被占用：lsof -i :39220（macOS/Linux）或 netstat -ano | findstr 39220（Windows）。
  • 运行 figmingo-mcp doctor 查看桥状态。
调用 get_html_replica_spec / import_html_replica 报错 Chromium 未安装 
npx playwright install chromium

然后重跑。

verify_html_parity 视觉 diff 失败
  • 先看 diff 图，定位是具体哪个 band。
  • 字体不同是常见根因；在 Figma 里安装原稿字体后再导入可消除。
  • 第三方 JS widget（如 affirm、PayPal）的 DOM 结构畸形时，提取器可能拿不到真实排版，需要手动 patch HTML。
如何更新 / 卸载 
# 更新
npm install -g figmingo-mcp@latest

# 更新后重新复制插件
figmingo-mcp doctor

# 卸载
npm uninstall -g figmingo-mcp
rm -rf ~/.figmingo

卸载后也可以顺手删除桌面上的 figmingo-plugin 快捷方式。

九、写在最后

figmingo-mcp 是本地优先方案：除调用 api.figma.com 外，所有数据、插件连接、Chromium 渲染都在你自己的机器上完成。 免费 Figma 套餐即可使用全部读取与写入能力，没有 Dev 席位或月度调用上限。

更深入的架构说明、工具契约与验收方案见 ARCHITECTURE.md；复刻实战心法见 docs/REPLICA-PLAYBOOK.md。
