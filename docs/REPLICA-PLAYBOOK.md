# Replica Playbook — HTML 复刻作战手册

> 沉淀自两道实战题的 solver + judge 双方经验：
>
> - **C1**（韩国攻略图复刻）：91 分，收敛到 2.457%，7 轮返修
> - **C2**（百度首页复刻）：PASS 93 分，1.96%，6 轮
>
> 目标：**下次复刻任务从第一轮就走对路，消除犹豫和歪路。**
> 按本文执行，C1 级别的题应在 3–4 轮内收敛，而不是 7 轮。

---

## A. 标准作战流程（6 步）

### A1. 测量先行——先写测量脚本，再写 CSS

**不要对着参考图"目测"调 CSS。** 动手写 HTML 之前，先写一个像素测量脚本（Python + numpy/PIL 即可），从参考图里量出：

- **取色**：背景色、文字色、边框色（取多个采样点求众数，避开 AA 边缘）
- **线条坐标**：分隔线、边框的精确 y/x 位置与粗细（扫描行/列的色值跳变）
- **文字 bbox**：每段文字的包围盒（阈值化后连通域），得到字号、行高、字距的像素真值
- **行宽**：同行文字的左右端点，推出容器宽度与对齐方式

> C1 solver 自述："如果再来一次，第一轮就建 numpy 测量脚本，可以 3–4 轮收敛而不是 7 轮。"
> 前 3 轮目测调参浪费的轮次，一次测量脚本就能省回来。

**落地步骤**：`measure.py` 输出一份 JSON（颜色表 / 线条表 / 文字 bbox 表），CSS 里所有数值必须能溯源到这张表。后续每轮返修，新的疑问（"这线多粗？""这字多宽？"）也回这张表里查/补测，不拍脑袋。

### A2. 字体环境锁定

1. **识别参考图字体/字重**：从测量脚本的文字 bbox 形态（字面宽、笔画粗细）+ 设计稿来源判断字体族与字重。
2. **CSS 显式锁定**：`font-family` 按回退链写全、`font-weight` 写死数值，不依赖浏览器默认。
3. **系统无匹配字体时**：立刻做 **A/B 单变量测试**——同一 HTML 只换 `font-family`/`font-weight` 一个变量渲染两张图，分别 compare，用 diffRatio 裁决，不猜。

> judge C2 建议 #3：字体识别应在第一轮固化。
> C1 r6 教训：同一轮同时改字体栈和字重两处，diff 变差时**无法归因**，等于白烧一轮。

### A3. 先量宽度，再调字重

字看起来"粗细不对"时，**第一反应是量行宽，不是改字重**。

> C2 实测：假设"参考图更粗"把字重 500→600，diff 反而变大。像素测宽发现真因是**字号 16px ≠ 参考 14px**——字宽差来自字号而非字重。

**判据**：同一行文字的像素宽度差 > 2%，先查字号/字距；宽度一致但笔画形态不同，才轮到字重/字体族。

### A4. bands 驱动迭代

每轮返修跑一次 `compare_html_to_image`，**`bandEdges` 按设计元素边界设置**（一条带 = 一个元素：搜索框一条带、导航一条带、页脚一条带……）：

- **只修高 ratio 带**：按 band diffRatio 降序修，不要全图撒胡椒面。
- **"哪里没问题"也要看**：0 差异带是确认书——这些区域冻结，后续轮次不得再动，防止回归。
- 差异跨带时，说明是结构性/全局性问题（字体、背景、布局骨架），回到 A2/A5 处理，不在带内缝补。

### A5. 单变量原则

- **每轮只改一处**，改完立即 compare，记录每轮 ratio 变化。
- 一轮改多处 = 无法归因 = 浪费一轮（C1 r6）。
- **结构性重构（拆 div、改布局骨架）后立即验证 position**：C1 r4 拆 div 后某元素 position 属性失效导致回归——重构轮的 compare 必须看 bands 里是否有**新出现的**差异带，不只是总 ratio。

### A6. 收敛判据（何时停手）

同时满足两条即判定**字形极限收敛**，停止返修：

1. **文字带外差异为 0**（布局、颜色、线条全部归零）；
2. **文字带差异连续两轮变化 < 0.1pp**。

继续返修只会得到负收益轮：C1 的字重微调轮、C2 的第 6 轮都是 ratio 不降反升。字形级差异受运行环境字体渲染限制，不是 CSS 能修的——收手，把结论写进交付说明。

## B. 阈值与判读

### B1. diffRatio 分档

| 总 ratio | 判定 | 行动 |
|---|---|---|
| ≤ 1% | 优秀 | 交付 |
| 1–2% | 达标 | 可交付；若文字带外仍有差异，顺手清零 |
| 2–3% | 字体受限收敛 | **必须确认差异 100% 落在文字/字形区**（bands + diff 图双重确认）才可停手 |
| > 3% | 布局问题 | 继续修，按 A4 找最高 ratio 带 |

### B2. diff 图判读（看形态，不只看数值）

| diff 形态 | 类型 | 对策 |
|---|---|---|
| **环状/描边状边缘高亮**（文字轮廓一圈红） | 字体 AA 类 | **不可再修**——字形渲染差异，属于收敛极限 |
| **实心块/大块连红** | 布局错位类 | **必须修**——位置、尺寸、颜色、缺元素，回 A 流程定位 |

### B3. 低对比小字区域单列

浅灰小字（低对比度文本）的 AA 差异**天然偏高**：灰字在白底上的边缘过渡带占比大，pixelmatch 对低对比边缘更敏感。判读时把这类区域**单独列出**评估，不要把它们的 AA 差异当作布局问题去"修"，也不要因它们拉高总 ratio 而误判未收敛。

### B4. 作弊红线

- 🚫 **禁止整页贴图当背景**（把参考图/截图直接铺成 background-image 凑像素一致）。
- ✅ **素材级小图允许 base64 内嵌**：logo、图标、产品图等设计素材可以内嵌，这是复刻素材不是作弊。
- 判据：贴进去的图如果是"排版结果"（整段版式）即作弊；如果是"设计原料"（独立素材）即合法。

## C. 工具速查

### compare_html_to_image（主力，每轮必跑）

一次调用 = 渲染 + pixelmatch 对比 + 分带定位。参数：

| 参数 | 说明 |
|---|---|
| `htmlPath` / `html` / `url` | 三选一指定页面 |
| `selector` | 只截某个元素（如 `#page`），推荐锁定复刻根节点 |
| `viewportWidth` / `viewportHeight` | 与参考图尺寸对齐（默认 1440×900） |
| `imagePath` | **必填**，参考图 PNG |
| `bands: N` | 等高分带（默认 10，0 = 关） |
| `bandEdges: [y…]` | **自定义分带边界，优先于 bands**；按设计元素边界设置（A4） |
| `maxRatio` | **passed = diffRatio ≤ maxRatio，默认 0.01**；返修轮调大（如 0.05）让调用"通过"以便专注看 bands 定位 |
| `threshold` | pixelmatch 单像素色差阈值，默认 0.1，越小越严 |
| `outDiffPath` | 落盘 diff 图（红 = 真实差异，黄 = AA） |
| `outRenderPath` | 落盘渲染 PNG——量行宽/取色时不用再调 render_html_screenshot |

**methodology 口径**（每次返回都带）：

- `antiAliasCountedInDiff: false`——`diffPixels`/`diffRatio` **不含** pixelmatch 标记的抗锯齿像素；`antiAliasPixels` 单列。看收敛趋势用 diffRatio，评估"剩余差异是不是全是 AA"时对照 antiAliasPixels。
- 尺寸差 > 2px（crop 容差）直接返回 `size_mismatch` 错误——先把视口/缩放对齐再比。

### render_html_screenshot

只渲染不对比。用途：拿渲染图去做测量脚本输入（A1）、或渲染中间态给人目检。`hideFixed` 可隐藏 fixed/sticky 元素，`settleMs` 控制渲染后等待。

### verify_html_parity（终验 gate）

有 Figma spec 时跑完整三关验收（content 文案/字体/颜色、structural ±4px、visual ≤1%），产出 `report.json`。返修循环里用 compare_html_to_image，**终验交付前**跑 verify_html_parity。

## D. 文案核对 checklist

C1/C2 都在这些点上考过——**逐字核对，不要只看词**：

- [ ] **撇号**：直撇号 `'` vs 弯撇号 `'`（英文所有格、缩写）
- [ ] **全角/半角**：标点与数字、括号的角式是否与参考一致（中文语境全角，混排时注意半角数字间距）
- [ ] **间隔号**：`·`（U+00B7）vs `・`（U+30FB）vs `•`（U+2022）——三个长得几乎一样
- [ ] **破折号**：`-` 连字符 / `–` en-dash / `—` em-dash / `−` 减号
- [ ] **箭头**：`→`（U+2192）vs `->` ASCII 拼写 vs 图标字体
- [ ] **日期/时间格式**：`2024.01.01` vs `2024-01-01` vs `2024/01/01`、前导零、星期写法
- [ ] 数字千分位、货币符号、百分号全半角
- [ ] 不可见差异：不换行空格 `&nbsp;`、零宽字符、大小写（i/İ 类）

方法：把参考图文案 OCR/人工誊抄后与 HTML 源码**逐字符 diff**，肉眼相似的字符一律查 Unicode 码位。

## E. 已知工具改进 backlog

judge 建议、尚未实现的工具增强（按价值排序）：

1. **diff 类型自动推断（AA vs 布局）**：对 diff 图做连通域形态分类——环状细边自动标 AA 类、实心块标布局类，把 B2 的人工判读自动化进返回体（如 `diffClassification: {aaLike: n, layoutLike: n}`）。
2. **低对比文字区自动宽容**：检测低对比文本区域，对该区域自动放宽 pixelmatch threshold（B3 的自动化），避免浅灰小字干扰总 ratio 判读。
3. **字体匹配自动探测推荐**：渲染 N 种候选字体/字重的同一文本，与参考图文字区自动比对，输出推荐 font-family/font-weight（A2/A3 的自动化）。

## F. Figma↔Chromium 字重映射

实测结论（C4）：**Figma `PingFang SC Medium` ≈ Chromium `font-weight: 600`，不是 500**。
直接按 CSS 惯例把 Medium 映射成 500 会整体偏细，文字带 diff 迟迟收不下去；改成 600 后字宽/字重同时对齐。

实用映射表（PingFang SC / 常见中文字体 → Chromium font-weight）：

| Figma 字重名 | Chromium font-weight |
|---|---|
| PingFang SC Light | 300 |
| PingFang SC Regular | 400 |
| PingFang SC Medium | **600**（非 500） |
| PingFang SC Semibold | 700（若 600 已被 Medium 占用，标题类可上 700，以字宽实测为准） |
| Inter Medium / Bold | 500 / 700（西文字体按惯例映射即可） |

判读方法不变：先量字宽差（A1），字宽对不上先调字号，字号对了再调字重档位。

### C4 收敛经验（两条可直接当判据用）

1. **非文字带 diff 可归零**：纯色块、描边、阴影这类非文字元素，只要几何和颜色量对了，diffRatio 能收到 0——非文字带还有残余 diff 时，不要归因于"渲染差异"，回去量几何/取色。
2. **< 0.6% 且纯 AA 描边即收敛**：总 diffRatio 低于 0.6%、且 diff 图上残余只是环状细边（antiAliasPixels 解释了绝大部分）时，判定收敛、停手交付——继续调参是负收益。
